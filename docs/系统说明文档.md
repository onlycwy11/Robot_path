# 多机器人集群调度系统

## 项目概述

本项目是一个多机器人集群调度系统，用于多层建筑环境中的机器人任务管理与路径规划。系统支持多种机器人类型（四足机器人 dog、人形机器人 human），能够在包含电梯和楼梯的复杂建筑环境中进行智能调度。

### 核心功能

- **任务调度**：根据任务优先级和机器人技能自动分配最优机器人
- **路径规划**：基于图算法计算最短路径，支持电梯和楼梯两种跨层方式
- **冲突解决**：自动检测和解决电梯预约冲突、楼梯会车冲突
- **实时状态监控**：通过 MQTT 协议获取机器人实时位置、电量、状态等信息

### 技术栈

| 类别 | 技术 |
|------|------|
| 语言 | Python 3.11+ |
| Web框架 | FastAPI |
| 数据验证 | Pydantic |
| 图算法 | NetworkX |
| 实时通信 | MQTT (paho-mqtt) |
| 容器化 | Docker |

### 一、图数据结构与路径搜索算法

#### 1.1 图的构建

系统将建筑拓扑转换为**加权有向图**结构：

- **节点（Vertex）**: 每个物理位置点（房间、电梯口、楼梯口等）
- **边（Edge）**: 连接两个节点的通道，权重为通行时间（秒）

```
Graph 数据结构:
┌─────────────────────────────────────────────┐
│  _nodes: Dict[str, Dict]                    │  节点字典
│    - key: node_name                         │
│    - value: {"floor", "building", "type"}   │
│                                             │
│  _edges: Dict[str, Dict[str, float]]        │  边字典
│    - key: from_node                         │
│    - value: {to_node: weight}               │
│                                             │
│  _adjacency: Dict[str, List[Tuple]]         │  邻接表（优化查询）
│    - key: node                              │
│    - value: [(neighbor, weight), ...]       │
└─────────────────────────────────────────────┘
```

#### 1.2 权重计算公式

边的权重（通行时间）根据通道类型计算：

| 通道类型 | 计算公式 | 参数说明 |
|----------|----------|----------|
| **平地行走** | `time = distance / speed_land` | speed_land = 1.5 m/s |
| **楼梯攀登** | `time = distance / speed_stair` | speed_stair = 0.5 m/s |
| **电梯运行** | `time = door_open + door_close + per_floor × n + door_open` | 见下表 |

电梯时间参数：

```
elevator_door_open   = 1.5 秒  （开门时间）
elevator_door_close  = 1.5 秒  （关门时间）
elevator_per_floor   = 1.75 秒/层 （运行速度）

示例：从1楼到4楼（跨3层）
total_time = 1.5 + 1.5 + 1.75×3 + 1.5 = 8.25 秒
```

#### 1.3 Dijkstra 最短路径算法

**算法原理**: 使用优先队列（堆）实现的标准 Dijkstra 算法，寻找单源最短路径。

```
伪代码:

function dijkstra(graph, start, target):
    初始化优先队列 PQ = [(0, start, [])]
    初始化已访问集合 visited = {}
    
    while PQ 不为空:
        cost, node, path = PQ.pop_min()  // 取代价最小
        
        if node in visited:
            continue
        
        visited.add(node)
        path = path + [node]
        
        if node == target:
            return (path, cost)  // 找到目标
        
        for neighbor, weight in graph.neighbors(node):
            if neighbor not in visited:
                PQ.push((cost + weight, neighbor, path))
    
    return (空路径, 无穷大)  // 不可达
```

**时间复杂度**: O((V + E) log V)，其中 V 为节点数，E 为边数。

#### 1.4 增强版 Dijkstra（带分段分析）

在标准 Dijkstra 基础上，`dijkstra_enhanced()` 返回路径分段信息：

```python
返回结构:
{
    "path": ["1_1_A", "1_1_E1", "4_1_E1", "4_1_B"],  # 节点路径
    "total_time": 15.5,                               # 总时间
    
    # 分段时间（用于电梯预约）
    "segments": {
        "before": 3.0,     # 到达电梯前的步行时间
        "between": 8.25,   # 电梯运行时间
        "after": 4.25      # 出电梯后的步行时间
    },
    
    # 电梯节点（用于预约）
    "elevator_nodes": ("1_1_E1", "4_1_E1")
}
```

**分段计算原理**:

```
function _calculate_segments(graph, path, e1, e2):
    before = 0    # e1 之前的边权重之和
    between = 0   # e1 到 e2 之间的边权重之和
    after = 0     # e2 之后的边权重之和
    
    idx_e1 = path.index(e1)
    idx_e2 = path.index(e2)
    
    for i in range(len(path) - 1):
        weight = graph.get_edge_weight(path[i], path[i+1])
        
        if i < idx_e1:
            before += weight
        elif idx_e1 <= i < idx_e2:
            between += weight
        else:
            after += weight
    
    return {"before": before, "between": between, "after": after}
```

#### 1.5 双电梯路径分析（跨楼运输）

当任务需要跨越不同大楼时，可能需要两部电梯：

```
路径结构:
[起点] → [电梯A起点] → [电梯A终点] → [换乘步行] → [电梯B起点] → [电梯B终点] → [终点]

分段信息 (PathSegments):
┌──────────────────────────────────────────────────────────────┐
│  before      │  between_1  │  transfer  │  between_2  │  after│
│  (步行到E1)  │  (电梯A运行) │  (换乘步行) │  (电梯B运行) │  (步行)│
└──────────────────────────────────────────────────────────────┘
```

#### 2.2 任务排列生成算法

**目的**: 在相同优先级和技能的任务组内尝试不同顺序，寻找全局最优。

```python
算法步骤:

1. 按 (priority, skill) 分组:
   groups = {
       (1, "dog"): [Task1, Task2],
       (1, "human"): [Task3],
       (2, "dog"): [Task4]
   }

2. 对每组生成排列:
   permutations = [
       permutations([Task1, Task2]),  # 2! = 2 种
       [Task3],                        # 1 种
       [Task4]                         # 1 种
   ]

3. 笛卡尔积组合所有组的排列:
   for combo in product(*permutations):
       yield flatten(combo)
   
   结果: 2 × 1 × 1 = 2 种全局排列
```

**复杂度控制**: 当组内任务数较多时，排列数会指数增长。实际应用中，同优先级同技能的任务通常较少（≤5），故复杂度可控。

#### 2.3 单任务分配算法

```
function _assign_single_task(task, current_time):

    # 1. 筛选可行机器人
    feasible_robots = [
        r for r in robots
        if r.skill == task.skill           # 技能匹配
        and r.charge >= min_threshold      # 电量充足
        and not r.is_charging              # 未在充电
    ]
    
    if not feasible_robots:
        return None  # 无可用机器人
    
    # 2. 为每个可行机器人计算路径代价
    best_robot = None
    best_total_time = ∞
    
    for robot in feasible_robots:
        available_time = max(current_time, robot.expected_available_time)
        
        # 计算取货路径和送货路径
        pick_info, deliver_info, path_results = select_best_path_with_elevator(
            start=robot.expected_position,
            pickup=task.start,
            target=task.target,
            available_time=available_time
        )
        
        # 计算总时间
        total_time = pick_info["actual_time"] + deliver_info["actual_time"]
        
        if total_time < best_total_time:
            best_robot = robot
            best_total_time = total_time
    
    # 3. 构建任务分配
    return build_assignment(task, best_robot, ...)
```

### 三、路径选择算法

#### 3.1 路径类型比较

系统支持多种跨层方式，`PathSelector` 会计算所有可行路径并选择最优：

```
路径类型对比:
┌──────────────┬────────────────┬─────────────────────────────┐
│   路径类型   │    适用场景    │           特点              │
├──────────────┼────────────────┼─────────────────────────────┤
│   楼梯路径   │   同楼跨层     │  速度慢但稳定，无需预约     │
│   单电梯路径 │   同楼/跨楼    │  速度快但需预约等待         │
│   双电梯路径 │   跨楼运输     │  需换乘，两次预约           │
└──────────────┴────────────────┴─────────────────────────────┘

选择原则: 最小化 total_time = actual_time + wait_time
```

#### 3.2 路径计算流程

```python
function select_best_path_with_elevator(task, robot, ...):

    path_results = {}  # 存储所有可行路径
    
    # === 计算楼梯路径 ===
    stair_path, stair_cost = stair_graph.dijkstra(start, pickup)
    if stair_path 可达:
        path_results["stair_1"] = {
            "path": stair_path,
            "actual_time": stair_cost,
            "wait_time": 0,  # 楼梯无需等待
            "type": "stair"
        }
    
    # === 计算电梯路径 ===
    for eid, graph in elevator_graphs:
        
        # 单电梯路径
        result = graph.dijkstra_enhanced(start, target)
        if result 可达:
            # 检查电梯预约可行性
            elev_start, elev_end, elev_ready = elevator.check_reserve(...)
            wait_time = max(elev_ready - available_time - before, 0)
            actual_time = elev_end + after - start_time
            
            path_results[eid] = {
                "path": result["path"],
                "actual_time": actual_time,
                "wait_time": wait_time,
                "type": "elevator",
                ...
            }
        
        # 双电梯路径（跨楼）
        if needs_two_elevators(start, target):
            for eid_2 in other_building_elevators:
                # 第一部电梯: start → transit
                res_1 = graph_1.dijkstra_enhanced(start, transit)
                # 第二部电梯: transit → target
                res_2 = graph_2.dijkstra_enhanced(transit, target)
                
                # 合并路径并计算总时间
                path = merge_paths(res_1["path"], res_2["path"])
                ...
                path_results[f"{eid}|{eid_2}"] = {...}
    
    # === 选择最优 ===
    best = min(path_results, key=lambda p: p["actual_time"])
    return best
```

```python
function Elevator.check_reserve(current_time, before, between, from_floor):

    # 电梯当前位置
    elevator_position = get_current_floor(current_time)

              = current_time                                (otherwise)

    # 检查调度表冲突
    for entry in schedule:
        if 时间重叠(elev_start, elev_end, entry.start, entry.end):
            # 有冲突，需要等待
            wait_time = entry.end_time - elev_start
            # 递归检查下一个可用时段
            return check_reserve(entry.end_time, ...)
    
    return (elev_start, elev_end, elev_ready)
```

### 四、冲突检测与解决算法

#### 4.1 电梯冲突检测

**检测原理**: 检查所有任务分配中电梯使用的时间窗口是否重叠。

```
冲突检测流程:

1. 收集电梯使用记录:
   elevator_usage = {
       "1_E1": [
           {"robot_id": 0, "time_window": (10.0, 18.5), "phase": PICK},
           {"robot_id": 1, "time_window": (12.0, 20.0), "phase": DELIVER}
       ],
       ...
   }

2. 对每个电梯的使用记录排序:
   usages.sort(by start_time)

3. 检查相邻使用是否重叠:
   for i, j in usages:
       if end_i > start_j:  # 时间重叠
           conflicts.append({
               "elevator_id": eid,
               "usage1": usages[i],
               "usage2": usages[j],
               "overlap_time": min(end_i, end_j) - max(start_i, start_j)
           })

4. 返回所有冲突（按开始时间排序）
```

**重叠判断**:

```
时间窗口 A: [start_A, end_A]
时间窗口 B: [start_B, end_B]

无冲突条件: end_A <= start_B  OR  end_B <= start_A
有冲突条件: end_A > start_B   AND  end_B > start_A
重叠时长: min(end_A, end_B) - max(start_A, start_B)
```

#### 4.2 电梯冲突解决策略

**Strategy 1 - 先到达者优先**:

```
原理: 最大化电梯利用率，不让电梯空闲等待

winner = 先到达的机器人  (start_time 较小)
loser  = 后到达的机器人

loser 需要选择替代路径（楼梯或等待电梯空闲）
```

**Strategy 2 - 最小代价增加** (默认使用):

```
原理: 选择代价增量最小的机器人改变路径，最小化全局延迟

计算步骤:

1. 计算两个机器人改路的代价增量:
   penalty_1 = stair_path_time - elevator_path_time (机器人1)
   penalty_2 = stair_path_time - elevator_path_time (机器人2)

2. 比较任务优先级:
   if task_1.priority > task_2.priority:
       winner = robot_2, loser = robot_1  # 高优先级保留电梯
   elif task_1.priority < task_2.priority:
       winner = robot_1, loser = robot_2

3. 同优先级时比较代价增量:
   if penalty_1 < penalty_2:
       winner = robot_2, loser = robot_1  # 改路代价小的去改路
   else:
       winner = robot_1, loser = robot_2

4. loser 查找替代路径:
   alternatives = find_stair_alternatives(loser_assignment)
   apply_best_alternative(loser, alternatives)
```

#### 4.3 楼梯冲突检测

**冲突类型**:

| 类型 | 场景 | 风险等级 |
|------|------|----------|
| `OPPOSITE_DIRECTION` | 双向会车（上楼vs下楼） | 高危 |
| `SAME_DIRECTION` | 同向超车（快vs慢） | 中危 |
| `INTERSECTION` | 交叉路口（横向vs纵向） | 低危 |

**检测流程**:

```
1. 收集楼梯使用记录:
   for assignment in assignments:
       for node in path:
           if "stair" in node.lower():
               stair_usages[stair_id].append({
                   "robot_id": robot_id,
                   "time_window": (stair_start, stair_end),
                   "direction": direction  # "up"/"down"/"horizontal"
               })

2. 判断方向:
   if next_floor > prev_floor: direction = "up"
   elif next_floor < prev_floor: direction = "down"
   else: direction = "horizontal"

3. 检查时间重叠并判断冲突类型:
   if 时间重叠:
       conflict_type = determine_conflict_type(direction1, direction2)
```

#### 4.4 楼梯冲突解决策略

```
解决规则:

1. 双向会车（最危险）:
   - 必须一方等待另一方完全通过
   - 等待时长 = overlap_time + safety_margin
   - 优先级高的先通过，同优先级先到达者先通过

2. 同向超车:
   - 低优先级机器人等待
   - 等待时长 = status_update_interval（安全间隔）

3. 交叉路口:
   - 低优先级机器人等待
   - 等待时长 = overlap_time

应用延迟:
   loser.start_time += delay_time
   loser.end_time += delay_time
   loser.elevator_reservations += delay_time  # 同步延迟电梯预约
```

```python
function Elevator.get_current_floor(current_time):

    if schedule 为空:
        return initial_floor
    
    # 按开始时间排序
    sorted_schedule = sort(schedule, by start_time)
    
    for entry in sorted_schedule:
        if current_time < entry.start_time:
            # 在当前任务开始前
            return prev_entry.to_floor if prev_entry else initial_floor
        
        elif start_time <= current_time <= end_time:
            # 在任务执行中
            return entry.to_floor
    
    # 在所有任务之后
    return last_entry.to_floor
```

```python
function RobotPositionTracker.update_position(current_time):
```

```python
function Robot.calculate_electricity_consumption(path):

    consumption = 0
    
    for segment in path:
        distance_m = euclidean_distance(node1, node2) / 100
        
        if is_elevator_segment(node1, node2):
            # 电梯段：低消耗
            consumption += distance_m × 0.001
        
        elif is_stair_segment(node1, node2):
            # 楼梯段：高消耗
            consumption += distance_m × 0.05
        
        else:
            # 平地段：中等消耗
            consumption += distance_m × 0.02
    
    return min(consumption, 100.0)  # 不超过100%
```

### 七、算法复杂度分析

| 算法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|------------|------------|------|
| Dijkstra | O((V+E) log V) | O(V) | 单次路径搜索 |
| 增强Dijkstra | O((V+E) log V + E) | O(V + E) | 带分段分析 |
| 任务排列生成 | O(k! × m) | O(k × m) | k=同组任务数, m=组数 |
| 单任务分配 | O(R × P) | O(P) | R=机器人数, P=路径数 |
| 电梯冲突检测 | O(A² × E) | O(A × E) | A=分配数, E=电梯数 |
| 楼梯冲突检测 | O(A × N) | O(A × N) | N=路径节点数 |
| 冲突解决 | O(C × A) | O(A) | C=冲突数, 迭代式 |
